## Shared architecture and operations

Next.js/React renders the workspace and uses Supabase Auth. FastAPI validates the bearer session and forwards user-scoped reads to PostgREST so row-level security applies. PostgreSQL functions guard state transitions; service credentials stay with the API and worker. Redis/Celery processes persisted webhook, outbound, and agent jobs; beat reconciles work after broker failures. Caddy and Docker Compose describe the intended two-host staging deployment. The [README](../../README.md) has local setup, environment variables, staging, and commands. Tests live under `apps/api/tests`; no real Meta sandbox acceptance test has passed.

## What remains before sandbox acceptance

The supplied remote Supabase project has migrations but no owner account or tenant. Supabase rejected the supplied four-character owner password. Channel asset IDs and tokens, Meta app configuration and subscriptions, and a public HTTPS API callback are still needed. After those exist, verify inbound and outbound messages on each authorized test channel, then test an AI reply and handoff. The local model endpoint is configured but depends on an external ngrok tunnel and has not passed a real Bangla/Banglish quality evaluation.

The sidebar now routes every observed Presswayy area, but parcels, calls, recordings, ads, broadcasts, chat summaries, billing, tutorials, support, external commerce connectors, and the website widget are availability pages, not implemented workflows. Train Content routes to the existing Agent Studio knowledge editor; Page-post import requires Meta assets and permissions. The Admin Agent currently handles stock, price, product drafts, and FAQ additions; it does not have general administrative powers. The repository has no production deployment or proven live Meta traffic at this point.
